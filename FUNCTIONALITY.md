# Функционал системы управления заявками

## 👤 ФУНКЦИОНАЛ ДЛЯ ОБЫЧНЫХ ПОЛЬЗОВАТЕЛЕЙ

### 1. Аутентификация
- **Регистрация** (`/register`)
  - Ввод имени, email и пароля
  - Валидация всех полей
  - Автоматическая роль: `user`
  - После регистрации - автоматический вход

- **Вход в систему** (`/login`)
  - Email и пароль
  - Получение JWT токена
  - Сохранение токена в localStorage
  - Автоматический редирект на /requests

- **Выход из системы**
  - Очистка токена
  - Редирект на /login

### 2. Управление своими заявками

#### 2.1 Просмотр списка заявок (`/requests`)
**Функции:**
- Полный список всех своих заявок с пагинацией (10 заявок на странице)
- Отображение: название, описание (первые 100 символов), категория, статус, дата создания
- Цветовые коды статусов:
  - 🔵 **New** - синий (новая заявка)
  - 🟡 **In Progress** - жёлтый (в процессе)
  - 🟢 **Resolved** - зелёный (решено)
  - 🔴 **Rejected** - красный (отклонено)

**Фильтры и поиск:**
- **Фильтр по статусу**: All, New, In Progress, Resolved, Rejected
- **Поиск**: по названию заявки (поиск по названию и описанию)
- **Пагинация**: переход между страницами
- При изменении фильтра - сброс на 1-ю страницу

#### 2.2 Создание новой заявки (`/requests/create`)
**Обязательные поля:**
- **Название** (title) - текстовое поле
- **Описание** (description) - текстовая область (5 строк)
- **Категория** (category) - выпадающий список (загружается с бэка)

**Действия:**
- ✅ **Создать** - сохранить заявку
- ❌ **Отмена** - вернуться к списку
- После создания - редирект на список заявок
- Статус новой заявки автоматически: **New**

#### 2.3 Просмотр деталей заявки (`/requests/:id`)
**Отображаемая информация:**
- Название
- Описание (полное)
- Категория
- Статус (цветной badge)
- Автор (имя пользователя)
- Дата и время создания

**История статусов**
- Полная аудит-тропа: кто и когда менял статус
- Показывает: старый статус → новый статус
- Информация о том, кто менял (имя админа)
- Дата и время изменения

**Доступные действия (только если статус = "New" и пользователь - автор):**
- **Редактирование** - можно менять:
  - Название
  - Описание
  - Категорию
  - ⚠️ **НЕЛЬЗЯ** менять статус и автора
- **Удаление** - полное удаление заявки
  - ⚠️ Только если статус = "New"

**Действия при других статусах:**
- 🔒 Редактирование НЕДОСТУПНО
- 🔒 Удаление НЕДОСТУПНО
- Можно только просматривать информацию и историю

## 👨‍💼 ФУНКЦИОНАЛ ДЛЯ АДМИНИСТРАТОРОВ

### 1. Доступ админа
- **Вход**: через `/login` с учётными данными админа (email: admin@example.com, password: admin123)
- **Админ панель**: доступна через кнопку **Admin Panel** в навбаре

### 2. Управление всеми заявками (`/admin`)

#### 2.1 Просмотр статистики (Dashboard)
**Статистика на главной админ панели:**
- 📊 **Total Requests** - общее кол-во заявок
- 🆕 **New** - количество новых заявок
- ⏳ **In Progress** - количество в процессе
- ✅ **Resolved** - количество решённых
- ❌ **Rejected** - количество отклонённых

**Обновление**: статистика обновляется при каждой загрузке страницы или после действия

#### 2.2 Управление заявками (Manage Requests)
**Функции:**
- Просмотр **всех заявок** в системе (не только своих!)
- Пагинация: 10 заявок на странице
- Информация в списке:
  - Название заявки
  - Описание (первые 80 символов)
  - Текущий статус (в выпадающем списке)
  - Автор (имя пользователя)
  - Категория
  - Дата создания

**Фильтры для заявок:**
- **Фильтр по статусу**: All, New, In Progress, Resolved, Rejected
- **Поиск**: по названию и описанию заявки
- **Пагинация**: перемещение между страницами

#### 2.3 Изменение статуса заявки
**Как работает:**
- Каждая заявка имеет выпадающий список со статусами
- Статусы: New, In Progress, Resolved, Rejected
- При выборе нового статуса:
  - ✅ Статус обновляется мгновенно
  - 📝 Автоматически создаётся запись в истории
  - 👤 Записывается, кто менял (ID админа)
  - 🕐 Записывается дата и время изменения

**Ограничения:**
- Админ может менять статус на любой из 4-х (нет ограничений)
- Админ МОЖЕТ менять статус даже на заявках других пользователей

#### 2.4 История статусов (Status History)
- Видна в деталях каждой заявки
- Показывает полную цепочку изменений
- Для каждого изменения:
  - Старый статус → Новый статус (цветные badges)
  - Кто менял (имя админа)
  - Когда менял (дата и время)

### 3. Управление категориями

#### 3.1 Просмотр категорий
- Кнопка **Show Categories** открывает раздел управления
- Список всех существующих категорий

#### 3.2 Создание новой категории
**Поля:**
- **Name** - название категории (обязательно)
- **Description** - описание (опционально)

**Действие:**
- Нажать **Add Category**
- Категория добавляется в БД
- Категория сразу становится доступной при создании заявок

#### 3.3 Удаление категории
- Кнопка **Delete** рядом с каждой категорией
- После удаления - категория больше недоступна
- ⚠️ Заявки с этой категорией остаются (категория просто удаляется из справочника)

#### 3.4 Редактирование категории
- ⚠️ Текущая версия: НЕ РЕАЛИЗОВАНО
- Можно только удалять и создавать новые

## 🛠️ ТЕХНИЧЕСКИЕ ДЕТАЛИ ЗАПРОСОВ

### Endpoints для пользователя:
- `POST /api/auth/register` - регистрация
- `POST /api/auth/login` - вход
- `GET /api/users/profile` - профиль пользователя
- `GET /api/requests/my-requests?...` - мои заявки с фильтрами
- `POST /api/requests` - создание заявки
- `GET /api/requests/:id` - детали заявки
- `PUT /api/requests/:id` - редактирование заявки
- `DELETE /api/requests/:id` - удаление заявки
- `GET /api/requests/:id/history` - история статусов
- `GET /api/categories` - список категорий

### Endpoints для администратора:
- Всё выше + 
- `GET /api/requests` - все заявки (с фильтрами)
- `PATCH /api/requests/:id/status` - изменение статуса
- `GET /api/requests/statistics` - общая статистика
- `POST /api/categories` - создание категории
- `PUT /api/categories/:id` - обновление категории
- `DELETE /api/categories/:id` - удаление категории
- `GET /api/users` - список всех пользователей

## 📝 ПРИМЕРЫ ИСПОЛЬЗОВАНИЯ

### Для пользователя:
1. Регистрируется
2. Создаёт заявку "Помощь с подпиской"
3. Видит статус "New"
4. Понимает, что можно отредактировать
5. Редактирует описание
6. Администратор видит заявку и меняет статус на "In Progress"
7. Пользователь видит изменение статуса и историю
8. Администратор меняет на "Resolved"
9. Пользователь видит готовую заявку ✅

### Для администратора:
1. Входит в админ панель
2. Видит статистику: 15 заявок (5 new, 7 in progress, 2 resolved, 1 rejected)
3. Фильтрует только "New" заявки
4. Видит 5 новых заявок
5. Начинает работать над каждой - меняет на "In Progress"
6. После решения - меняет на "Resolved"
7. Проблемные - меняет на "Rejected"
8. Добавляет новую категорию "Billing"
9. Удаляет старую категорию

## ⚠️ ВАЖНЫЕ ОГРАНИЧЕНИЯ

1. **Пользователь МОЖЕТ редактировать заявку ТОЛЬКО если:**
   - Он автор заявки
   - Статус = "New"
   - Не может менять статус

2. **Пользователь МОЖЕТ удалить заявку ТОЛЬКО если:**
   - Он автор
   - Статус = "New"

3. **Админ НЕ может:**
   - Редактировать содержимое заявки
   - Удалять заявки
   - Только менять статусы и управлять категориями

4. **Все действия логируются:**
   - История статусов сохраняется
   - Видно кто и когда менял
